## 1 这份作业要做什么

老师的要求可以拆成三组：

**第一组：三份过程文档 + 四份原有资料**

1. `1业务挖掘.md` —— 判断这个问题是否值得立项；

1. 用 **FastAPI** 提供后端接口；

4. 做 **权限分层**：管理员（SaaS）+ 分层用户。

**第三组：一套《企业报价包》（商务与交付模块）**

按《FDE 企业报价与 ROI 测算》课程要求，把同一个项目拆成成本、人天、Token、部署、ROI、报价单六件产出，见 [报价包/](报价包/README.md)。

本文件夹按这三组要求逐项交付。

## 3 项目一句话

**仓储高峰补员的真正瓶颈不是“招不到人”，而是“人到岗了却不知道能不能直接上岗”，以及“班次交接没有具名确认”。**

三份文档沿着 FDE 的业务挖掘、现场调研两个阶段推进，把这个判断从假设变成有证据的问题；MVP 则把“需求结构化、缺口三分、人员匹配、交接校验、权限审计、知识问答”做成可运行的最小闭环。

核心量化结论（合成演练数据，非真实客户数据）：

- 需求 38 人，可立即上岗 27 人，覆盖缺口 11 人；
- 缺口拆分为 **培训缺口 8 人 + 技能缺口 3 人**，两者不能合并；
- 夜班交接 24 项模板实际只填 9 项，漏 6 项，次班返工约 4.5 人时；
- 到岗即可独立上岗率 71%，试点目标 ≥ 90%。

## 5 如何复核

### 5.1 读文档

按 `1 → 2 → 3 → 4` 的顺序读。三份文档中的数字分为 `[公开]`、`[合成]`、`[待核实]` 三类，请重点看每份文档末尾的“待核实清单”和“交给下一阶段”，那是下一步真正要做的取证工作。

### 5.2 跑 MVP

```bash
cd mvp
python3 -m pip install -r requirements.txt
python3 -m uvicorn app.main:app --reload --port 8000
```

打开 http://127.0.0.1:8000 ，用不同账号登录：

- `admin / admin123`：管理员（SaaS），可跨租户、看审计；
- `lin.yizhou / demo123`：排期协调员，提交工单；
- `fu.jing / demo123`：质量复核，审批工单；
- `ye.shu / demo123`：只读用户，只能看。

建议按这条路径操作一遍：登录排期协调员 → 查看缺口分解 → 提交工单 → 切换到质量复核 → 审批通过 → 切回排期协调员 → 填写交接单 → 确认交接 → 打开审计页看哈希链。

### 5.3 跑测试与 Harness

```bash
cd mvp
python3 -m pytest -q
python3 -m app.harness
```

预期：`27 passed`；Harness 31 项检查通过，得分 ≥ 90，检索首位命中率 0.9，引用覆盖率和拒答准确率均为 1.0。

### 5.4 读报价包

按 `0 → 6` 的顺序读（[报价包/README.md](报价包/README.md) 有索引）。先看 `5-客户ROI一页纸.md` 判断值不值，再看 `6-正式报价单与谈判底线清单.md` 看多少钱；`1–4` 是支撑报价的三张测算表，重点核对第 4 节“数字咬合校验表”。

## 7 证据纪律与已知限制

1. 所有访谈与现场数据来自 FDE 训练中心的**合成演练**，不是上海外服真实业务数据；
2. 4 份原有资料来自上海外服官网公开页面，抓取日期 2026-11-19，属于宣传口径；
3. 官网的“400 家门店、700 人次/月、95% 到岗率”只作为行业参照，未套用到本项目；
4. MVP 未接入真实 WMS、培训台账、候选人库，也未做真实身份认证；
5. RAG 使用 BM25 与抽取式回答，不是大模型生成，优势是可追溯，局限是语义泛化弱；
6. 人员匹配是规则打分，不构成录用、派岗或排班决定；
7. 客户试点、真实验收、上线与运营均未发生，文档中不虚构这些结果。
