# 4 部署方案对比表与推荐配置单

> 练 4 · 对应第 04–05 章 · 产出：报价包第 4 件
> 项目：仓储高峰补员与班次交接 · 业务核对助手（3 仓）
> 作者：宋佳威（F2505437，F250117）· 日期：2026-11-26

## 1 第一步：API 还是私有化（决策表）

| 判断项 | 本项目情况 | 倾向 |
| --- | --- | --- |
| 数据合规 | 姓名 / 电话 / 证件号可脱敏；无金融、政务、医疗级强监管 | 调 API |
| 用量规模 | 546 万 Token/月，量小且随高峰波动 | 调 API |
| 模型能力 | 分类抽取 + 规则问答，14B 级开源模型即可满足 | 两者皆可 |
| 运维能力 | 客户无专职运维，我方也只承诺轻运维 | 调 API |
| 响应延迟 | 班前会 10 分钟窗口，公网往返可接受（P95 < 3 秒） | 调 API |

**结论：主推 API。** 私有化只在两种情况下升级：客户要求人员数据完全不出内网，或用量超过盈亏平衡点。

## 2 第二步：显存三件套（自建方案才需要的账）

业务假设：14B 模型、INT8 部署、上下文 4,096 Token、峰值并发 6 路。

| 项 | 公式 / 取值 | 结果 |
| --- | --- | --- |
| 权重显存 | 14B × 1 字节（INT8） | 14.0 GB |
| KV Cache | 192 KB × 4,096 × 6 路 | 4.5 GB |
| 运行开销 | (14.0 + 4.5) × 15% | 2.8 GB |
| **总显存** | 权重 + KV + 开销 | **21.3 GB** |

选型判断：

- RTX 4090 24 GB 单卡可跑，余量 2.7 GB，**生产需双副本 → 2 卡 / 2 台**；
- 若把并发提到 8 路，KV 涨到 6.0 GB、总显存 23.0 GB，4090 余量只剩 1 GB，不安全，须换 L20 48 GB；
- 结论：上下文与并发是可谈判参数，先问清客户的班前会峰值并发，再定卡，而不是先买卡。

## 3 第三步：三种方案三年总账

| 方案 | 构成 | 年成本（元） | 首年成本（元） | 说明 |
| --- | --- | --- | --- | --- |
| **API（推荐）** | 模型 151 + 应用与数据库云主机 9,600 | **9,751** | 9,751 | 零固定算力成本，弹性无限；数据脱敏后出网 |
| 自建（云租 GPU） | 2 × RTX 4090 云租 28,032 + 应用主机 9,600 + 运维增量 30,000 | **67,632** | 67,632 | 双副本；GPU 闲置即浪费 |
| 自建（自购） | 整机 2 × 4090 60,000 按 3 年折旧 20,000 + 电费 8,829 + 运维 30,000 | **58,829** | 118,829 | 首年含采购；3 年 TCO 176,487 |
| 混合 | 敏感资质库自建 1 × 4090 云租 14,016 + 应用主机 9,600 + 通用能力 API 60 + 运维 15,000 | **38,676** | 38,676 | 单副本无高可用；人员数据本可脱敏，收益有限 |

电费口径：`整机功耗 1.0 kW × 24 × 365 × 0.8 元/度 × PUE 1.4 ≈ 9,811 元/年`（自购方案按 0.9 kW 轻载取 8,829 元）。

## 4 盈亏平衡点

```
临界月 Token 量 = 自建月固定成本 ÷ API 每百万 Token 综合单价 × 1,000,000
```

| 输入 | 数值 |
| --- | --- |
| 自建月固定成本（云租 67,632 ÷ 12） | 5,636 元/月 |
| API 综合单价（12.6 元 ÷ 5.4595 百万 Token） | 2.313 元/百万 Token |
| **临界月 Token 量** | **≈ 24.4 亿 Token/月** |
| 本项目当前月用量 | 546 万 Token（约 2.2% 的临界值） |

**判断：当前用量离自建盈亏平衡点差约 45 倍，自建在任何口径下都不划算。** 只有当客户把同样的能力铺到数百个仓、用量涨到十亿级，才需要重算这条线。

## 5 推荐配置单（API 方案）

| 项 | 配置 | 数量 | 月费（元） |
| --- | --- | --- | --- |
| 应用服务器 | 2 vCPU / 4 GB / 40 GB SSD | 2（主备） | 320 |
| 数据库 | PostgreSQL 2 vCPU / 4 GB / 100 GB SSD | 1（主备高可用） | 280 |
| 对象存储 | 100 GB（知识库、附件、审计归档） | 1 | 40 |
| 公网带宽 | 5 Mbps | 1 | 120 |
| 备份 | 7 天自动快照 | 1 | 40 |
| **合计** | — | — | **800 元/月（9,600 元/年）** |

配置依据：

- 并发只有 24 个内部用户、峰值 8 路，2 vCPU 足够；业务瓶颈在数据库与知识库检索，不在 CPU；
- 审计哈希链与交接记录需保留，存储按 3 年、每年约 30 GB 估 100 GB；
- 生产环境主备而非单机，避免“默认单机交付后被可用性追责”。

## 6 推荐方案与取舍理由

**推荐：API 方案。**

| 对比项 | API | 自建（云租） | 混合 |
| --- | --- | --- | --- |
| 年成本 | 9,751 元 | 67,632 元 | 38,676 元 |
| 固定投入 | 0 | 5,636 元/月 | 1,168 元/月 |
| 合规 | 脱敏后可接受 | 数据不出内网 | 敏感数据不出内网 |
| 运维负担 | 轻 | 重（GPU 驱动、模型更新） | 中 |
| 弹性 | 无限 | 受卡数限制 | 部分受限 |

**不选自建**：成本是 API 的 6.9 倍，且客户没有运维团队；为了 24 个用户养两张 GPU，边际成本永远收不回来。

**不选混合**：本项目最敏感的是人员资质，但资质本身可脱敏（姓名换工号），没有必要为它单独建一套单副本推理机；混合方案既没有合规硬收益，又多了一套要维护的系统。

**留一个升级口**：若客户合规部门要求“人员数据完全不出内网”，按第 3 节自建（云租）方案另评估报价，写进练 6 的可选条款，不默认包含。
