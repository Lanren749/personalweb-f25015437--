# KB-04 权限、审计与试点验收

> 来源：质量复核访谈、权限设计评审（合成演练）
> 版本：v0.3（2026-11-19）

## 角色分层

系统采用五类角色，权限自上而下收敛：

| 角色 | 说明 | 典型职责 |
| --- | --- | --- |
| saas_admin 管理员（SaaS） | 平台级管理员 | 租户与用户管理、系统配置、全局审计 |
| tenant_admin 业务管理员 | 租户级管理员 | 维护规则与知识库、审批例外、查看本租户全部工单 |
| dispatcher 排期协调员 | 业务经办 | 创建补员工单、维护名单、发起交接 |
| reviewer 质量复核 | 独立复核 | 审核工单、驳回、确认交接质量 |
| operator 一线经办人 | 现场操作 | 查看本人范围工单、录入交接内容 |
| viewer 只读用户 | 客户或观察者 | 只读查看，不得修改 |

## 最小权限与租户隔离

用户只能访问所属租户的数据；平台管理员跨租户访问必须留审计记录。人员手机号等敏感字段默认脱敏展示，只有业务管理员及以上可查看完整值。任何角色都不得删除审计日志。

## 职责分离

同一人不得同时完成"提交"与"审批"两个动作。工单创建人或提交人不能审批自己的工单；审批必须由 reviewer 或 tenant_admin 完成，且审批人不能是提交人。交接确认应由接班方完成，交班方不得代签。

## 审计五要素

每条审计记录必须包含：操作者、操作时间、动作、对象、变更前后值、理由。审计日志使用哈希链串联，任一历史记录被修改会导致后续哈希校验失败。审计查询仅对 saas_admin、tenant_admin 开放。

## 知识库回答规则

知识库回答必须满足：

1. 只能基于已入库资料，采用抽取式回答，不生成资料中没有的数字或结论；
2. 每条回答必须给出至少一条来源引用，包含文档编号与小节；
3. 检索置信度不足时必须明确拒答，并列出"需要补充的资料"或"转人工"；
4. 合成资料与真实客户资料必须可区分，回答中标注来源性质。

## 试点验收标准

| 编号 | 指标 | 目标 |
| --- | --- | --- |
| SC-01 | 需求单完整率 | ≥ 95% |
| SC-02 | 到岗即可独立上岗率 | 从 71% 提升到 ≥ 90% |
| SC-03 | 交接清单完整率 | 100% |
| SC-04 | 交接漏项数 | ≤ 2 项/班次 |
| SC-05 | 成功越权次数 | 0 |
| SC-06 | 知识问答可追溯率 | 100%，无依据必须拒答 |

试点期间出现无证上岗、成功越权、审计链断裂任一情况，立即暂停并回退人工清单。

## 数据留存与删除

交接记录与审计日志至少保留一个完整高峰周期再加三个月。具体年限以客户合同与公司制度为准 [待核实]。删除操作必须由业务管理员发起、质量复核批准，并保留删除原因。一线用户不得删除任何业务记录。
